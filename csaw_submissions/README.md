# CSAW 2025 AI Hardware Attack Challenge — Submissions

NYU CSAW AI Hardware Attack Challenge 2025. Every Trojan here was generated by
one autonomous, self-verifying AI pipeline built on six composable models;
no RTL or testbench was hand-written by a human. The pipeline is documented in
[`PIPELINE.md`](PIPELINE.md) and implemented in [`../csaw_aha/`](../csaw_aha/README.md).

> **AI generator:** Anthropic Claude `claude-opus-4-8`, driven through the Claude
> Code agentic harness; framework = the six *Prebuilt AI Technique* models. Full
> logs per challenge in each `ai/` directory. (Required by the rules; no logs ⇒ DQ.)

Each challenge directory is a self-contained submission in the required layout:

```
<challenge>/
├── README.md     how AI was used, how the Trojan works, how to test, rubric
├── rtl/          modified RTL (only the changed files differ from the golden IP)
├── tb/           exploit testbench demonstrating the Trojan
├── synth/        Yosys sky130 script (synth_trojan.ys)
├── synth-run/    synthesized gate-level netlist
└── ai/           complete AI interaction log
```

## Reproduce

Tools: Icarus Verilog + Yosys (the competition Docker, or any OSS-CAD suite).

```bash
# One-command regression over a built submission (the pipeline's own gate):
python -m csaw_aha verify c1_easy --submissions csaw_submissions \
       --source csaw_submissions/_challenge_source --synth

# Or by hand, per challenge (see each README for exact commands):
iverilog -g2012 -o x.out -s <orig_tb>   rtl/*.v <golden_tb>   && vvp x.out   # functionality
iverilog -g2012 -o y.out -s <exploit_tb> rtl/*.v tb/<exploit> && vvp y.out    # exploit
yosys -q synth/synth_trojan.ys                                                # synthesis
```

`_challenge_source/` holds the unmodified golden IPs for diffing and for the
original testbenches.

## Notes on verification

- Challenge 1 (AES) uses the original `tb_aes`; all three show the untriggered
  path is bit-identical and synthesize to sky130.
- Challenge 2 (wbuart32) original benches use a Verilator C++ harness; in this
  offline environment normal operation is proven by in-bench normal-op checks
  plus the structural argument that the trigger is unreachable by ordinary
  traffic (run the Verilator benches in the Docker for the golden pass). Exploit
  benches drive the real receiver and are fully simulation-verified.
- The OpenTitan final is submitted as the pipeline's design + patch + exploit
  sequence; its DV runs in the official OpenTitan container per the rules.
